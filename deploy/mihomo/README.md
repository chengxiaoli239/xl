# lottery_xl 按账号独立选择代理节点

后台账号列表 → **代理设置**：可以粘贴返回 YAML 的 HTTPS 订阅直链，或上传 Clash
YAML 文件；预览节点后只导入所选项，再启动、测试出口，最后为指定账号绑定节点。
导入、启动、测试不会自动登录盘口、下注、改变任何账号，或修改服务器默认网络。

## 行为与边界

- 不开启 TUN、透明代理、系统 HTTP_PROXY，不接管服务器 DNS。管理接口仅监听
  `127.0.0.1:17990` 并要求密钥；节点仅监听 `127.0.0.1:18100–18115`。
- 每个节点有独立 Mihomo 进程、固定端口和不可变配置。导入相同配置去重；更新的
  配置成为新节点，不覆盖旧节点。导入/启动 B 不重启 A；账号切换只更新一行账号数据。
- 节点供多个账号复用；给账号 A 改选节点不改变 B。绑定同一节点的账号共享出口。
- 只有 `proxy_type=4`、账号代理开关及对应场景开关开启时走绑定节点；其他代理商
  保持原实现，直连账号保持原路径。全局 `CURL_POXY_STATUS` 仍保留原有主开关语义，
  部署不自动更改它；应先确认它已开启再试用代理。
- 无节点绑定或节点故障不回退到其他账号节点或公网直连。管理页可先关闭账号代理，
  或改回原代理商。**回滚旧应用代码前先切回所有 provider 4 账号**。
- 当前支持云服务器模式、盘口 9/10 的 Lucky5 链路；这些盘口的旧 Seven 接口会
  对使用新代理的账号明确拒绝请求。本地 Windows 客户端和其他旧盘口未接入。
- 支持标准 ss/vmess/vless/trojan/hysteria2/http/socks5 节点及所列 ws/grpc/reality
  字段。非标准扩展字段会拒绝导入，不默默丢失节点选项。
- 上传需有 `proxies:` 节点列表；仅有 `proxy-providers:` 的配置不支持。不会导入 YAML
  内的规则、DNS、监听、控制接口或任意路径字段；不是直接执行完整机场配置。
- 本轮为 YAML 导入，不支持把原始 `ss://` / `vless://` URI 粘贴到订阅 URL 输入框。
  请使用供应商提供的 Clash YAML 订阅或导出的 YAML 文件。
- HTTPS 订阅直链不跟随重定向、不访问私网/云元数据地址；最多 1 MB，最多预览
  200 个节点。只保存所选节点，订阅 URL 不持久化，不定时更新；避免后台更新改变
  在线账号出口。重新导入后由管理员显式切换账号。
- 初始最多保存 16 个节点、同时启动 8 个，节点不删除、不复用端口，避免旧绑定误指
  向新节点。扩大容量/回收节点应由运维核查绑定后进行。

## 部署准备

所有步骤在批准的发布窗口执行；本文件不是“已经上线”的证明。

1. 核对并备份线上 Git 状态、账号代理字段、数据库结构；保留已有生产修改。
2. 固定并验证官方 Mihomo 版本（测试使用 v1.19.31），核验发行资产 SHA-256，安装
   Linux amd64 compatible 内核到 `/usr/local/bin/mihomo`。不可覆盖其他项目的内核。
3. 将 `node_manager.py` 安装到 `/opt/xl-node-manager/node_manager.py`，root 所有且
   0755；在 `/opt/xl-node-manager/venv` 建专用 venv，仅安装 requirements.txt。
   不依赖/升级系统 Python 包。Python 3.9+、systemd 247+。
4. 创建 `/etc/xl-node-manager` 为 root:www 0750，生成随机 API 密钥文件
   `/etc/xl-node-manager/api-secret`，root:www 0640。`www` 必须替换为已验证的
   PHP-FPM 运行组，不要扩大其他目录权限，不要打印密钥或放在 Web 根目录。
5. 安装 `deploy/systemd/xl-node-manager.service`，`daemon-reload` 后启动该独立服务。
   DynamicUser + StateDirectory 会管理 `/var/lib/xl-node-manager` 私密目录。
   服务通过 LoadCredential 读取密钥；只有管理进程读取节点密码。PHP 只存节点端口。
6. 新增 `proxy_node_port` 字段需执行本次指定迁移
   `m260921_160000_add_account_proxy_node_port`。不要无审查地执行全部待运行迁移。
   默认 0，不修改已有账号代理选择。上线前评估表大小/数据库 DDL 锁；字段迁移完成
   后刷新 Yii schema 缓存。缺少该字段时旧账号照旧，新代理保存会提示先迁移。
7. 发布本次审核过的应用文件，按已有发布流程安排 PHP-FPM 和长期 worker 采用新代码。
   禁止在执行中直接批量切换账号。首次部署不能仅更新 Web 而让旧 worker 使用 provider 4。
8. 核对所有监听都在回环地址，安全组不开放管理/节点端口。节点管理页面必须通过
   HTTPS 或受保护的 SSH 隧道访问，避免订阅密钥在现有明文 HTTP 站点上传输。

无节点时管理服务可启动但不启动任何 Mihomo 子进程；新功能不会改变旧账号路由。
正常导入、选择节点无需重启管理服务。**重启管理服务会重启它管理的节点进程**，
因此管理服务升级也需要维护窗口。节点意外退出会显示未启动，可单独启动恢复；
不会自动重试业务请求或触发下注。

## 小范围启用

1. 管理员 UID 1 导入 1–2 个节点。预览有效期 5 分钟，重开预览会替换上一次预览。
2. 启动所选节点，点击“测试出口 IP / 地区”：仅经该节点访问 Cloudflare trace，
   返回出口 IP 和国家代码（香港 HK），不携带盘口账号、Cookie 或下注请求。
3. 从具体账号的“代理设置”选择节点、代理总开关、登录/接口开关。保持同一账号的
   登录和接口出口一致通常更稳；只有保存当前账号才改变该账号。
4. 先选择一个授权测试且无执行中请求的账号，按需由用户重新登录。观察正常业务后
   再逐个启用其他账号；不需要代理的账号保持关闭。
5. 失败时关闭该账号代理或切回原代理商；其他账号绑定保持不变。

不要承诺任意节点必为香港或必然绕过盘口限制。节点名称不是地区验证结果。

## 验证

```sh
php tests/proxy_mihomo_regression.php
php tests/proxy_retry_account_regression.php
/path/to/venv/bin/python tests/test_node_manager.py -v
MIHOMO_BINARY=/absolute/path/to/mihomo /path/to/venv/bin/python tests/test_node_manager.py -v
```

使用模拟账号、临时目录、回环 HTTP 上游。双节点实测验证不同出口、重复导入、
新增节点不重启旧节点、单节点故障不影响另一节点。实际香港出口与真实账户业务
必须等用户配置节点后再分阶段验证。
